Early questions

  • can i run LoRA on the Pi?
    • train on laptop and only apply/merge the finished LoRA on the Pi
    • pick the base image model first since a LoRA is tied to its base model
    • LoRAs trained on SDXL transfer unreliably to SDXL-Turbo
    • my silhouette gate throws away most texture, so measure a prompt-only baseline before training anything
  • concepts:
    • a forward pass runs the model, and a backward pass computes how to improve it. this is why training needs far more memory than inference
    • distillation (turbo) trains a fast student to imitate a slower teacher. it’s fast because of fewer steps, not a smaller model, and it’s fragile to fine-tuning
  • my mac: an M4 Pro with 24 GB is plenty for SD 1.5 LoRA training, tight for SDXL training… the Pi’s 8 GB is still the real limit. I do have a NVIDIA graphics card on my windows PC. 3060ti.

planning decisions

  • mac-first workflow: develop prompts and compare quality on the mac, then confirm on the Pi
    • speed memory and temperature don’t transfer
    • quality only transfers if the model, size and quantization match
    • write the test harness against an OpenAI-style local endpoint, so only the base URL changes between machines
  • models in my plan: Moonshine (speech), a small Gemma (translation and subject), SDXL-Turbo (images). The silhouette gate will be custom code.
  • LMStudio vs Ollama: LM Studio is good for exploring, and Ollama is what my plan uses on the Pi

moonshine research

google’s Gemma Translator

  • read through repo
  • Google uses Gemma 4 E2B through LiteRT-LM. the model is imported as gemma4-e2b and litert-lm serve exposes an OpenAI-compatiable API on port 9379
  • Moonshine speech-to-text matches my approach
  • servery.py only proxies requests to the llm
  • the translation prompt is in TranslatorApp.jsx. it asks for a JSON object with a translation field, and warns against Markdown fences
    • Versions are pinned: litert-lm==0.13.1 and moonshine-voice==0.0.65.
  • Their systemd design runs everything as one service, assumes a network, and launches the display through desktop autostart. — mine will differ

ollama E2B

  • ollama’s E2B and Google’s gemma4-e2b are the same model made by Google, packaged differently.
    • ollama runs a llama.cpp-style conversion,
    • google’s project uses its own LiteRT-LM file
