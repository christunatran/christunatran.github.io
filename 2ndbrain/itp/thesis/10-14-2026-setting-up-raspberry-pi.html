goals

The core loop:

  1. Vietnamese speech is transcribed (Moonshine).
  2. It’s translated to English and turned into an image subject (Gemma).
  3. A black-and-white silhouette is generated (Stable Diffusion, likely SDXL-Turbo) and cleaned up by the silhouette gate.
  4. The silhouette joins a six-slot procession on six small LCD panels in a hexagon, behind mulberry or giấy dó paper.

local AI primer

  • a model is a large file of learned numbers (weights)
  • a runtime is a program that runs the model, i’ll use:
    • Ollama, easiest way to run text LLMs
    • LiteRT-LM, what Gemma Translator uses
    • PyTorch, what runs Stable Diffusion
  • quantization stores the weights with fewer bits. shrinks memory use and speeds things up at a small cost in quality, allowing LLMs to fit on a Pi at all.
  • tokens are word pieces. LLM speed is measured in tokens per second
  • temperature controls randomness. it should be low for translation
  • on a Pi, everything runs on the CPU and is limited by memory. small models (around 1-2B parameters) are realistic.

E00–E02: Raspberry Pi setup and development workflow

Date: October 14, 2026 Question: Can I get the Pi 5 running headless (no monitor, keyboard or mouse) and set up a workflow where I edit and run code on it from my laptop? Hypothesis: Yes, using Raspberry Pi Imager with pre-configured Wi-Fi and SSH, then VS Code Remote-SSH.

Setup

  • Hardware: Raspberry Pi 5 (8 GB), official 27W USB-C power supply, microSD card. No monitor, keyboard or mouse.
  • OS: Raspberry Pi OS (64-bit), flashed with Raspberry Pi Imager. (Confirm: desktop version, which the display work needs later.)
  • Imager settings:
    • Hostname: tunapee
    • Username: tunapee
    • Wi-Fi and country (US) set in Imager
    • SSH enabled with password authentication
    • Raspberry Pi Connect: skipped (cloud service; can enable later)

What I did

E00: First boot and hello world

  1. Flashed the SD card, inserted it, powered on, waited for first boot.

  2. Connected from my laptop: ssh tunapee@tunapee.local

  3. Ran a first Python command on the Pi:

    python3 -c "print('xin chao from the lantern')"→ xin chao from the lantern

  4. Checked memory, temperature and power (results below).

E02: VS Code workflow (steps 1–5)

  1. SSH key: made a key on my laptop (ssh-keygen -t ed25519) and copied it to the Pi, so I log in without a password.

  2. SSH shortcut: added a Host pi entry to ~/.ssh/config on my laptop, so ssh pi connects.

  3. VS Code Remote-SSH: installed the extension and connected to the Pi. VS Code’s file explorer and terminal now run on the Pi.

  4. Project folder: created ~/lantern with notebook/, src/ and experiments/. Added technical plan.md; silhouette_pipeline.py and lantern_archive.py go in src/ (needed from E8 on).

  5. Python virtual environment:

    python3 -m venv --system-site-packages .venvsource .venv/bin/activate

    --system-site-packages keeps preinstalled Pi libraries (like gpiozero, for the playback button later) available. Selected .venv as the interpreter in VS Code.

  6. Git and GitHub:

    • git config --global user.name / user.email, then git init
    • Renamed the branch to main (git branch -m main) and made main the default for new repos
    • Added .gitignore (virtual environment, cache files, models, archive, silhouettes, *.png, *.wav)
    • First commit, published to a private GitHub repository from VS Code’s Source Control panel

What I learned

  • Two different prompts: $ is the terminal (Linux commands like cd, git, python3 -m venv); >>> is inside Python, for Python code only. exit() leaves Python.
  • Virtual environments keep each project’s Python libraries separate; the prompt shows (.venv) when one is active.
  • SSH keys replace typing a password on every connection.
  • Git vs GitHub: Git tracks file history on the Pi; GitHub is the online backup.
  • .gitignore keeps out files that are huge (models, virtual environment), can be recreated (cache files, generated images), or private (recordings and the archive of people’s speech).
